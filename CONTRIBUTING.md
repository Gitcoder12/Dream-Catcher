# Contributing to the Portfolio Ecosystem

Dream-Catcher coordinates target-company research; each project repository remains responsible for its own code, tests, issues and releases.

## How to contribute

1. Choose a repository from REPOSITORY_TARGET_MATRIX.md.
2. Read its README and identify the current implemented scope.
3. Inspect its activity log and feature plan before opening a duplicate issue.
4. Propose one bounded change with a problem statement, owner, acceptance criteria and test plan.
5. Work on a feature branch and submit a pull request.
6. Include exact validation commands/results, limitations and links to evidence.
7. Update the repository activity log after the work is committed or merged.

## Company research contribution

Add only employers with a credible technical fit. Include at least one current official source for a public project/team and one official careers link. Separate public leadership from project contributors. Record the page date and the date checked. Never infer private reporting lines or collect private contact details, personal-life data, leaked material, confidential work or classified information.

## Repository-target mapping rules

- Every repository should map to one or more plausible target organisations and relevant technical teams.
- Explain why the project's skills or use case are relevant.
- Do not imply that a listed company uses, endorses, funds or requested a repository.
- Upstream repositories must not be represented as original authorship.
- Archived repositories are read-only unless deliberately reactivated.

## Review checklist

- [ ] The work is tied to a specific repository and roadmap item.
- [ ] The README explains the project to both beginners and technical reviewers.
- [ ] The change has tests or reproducible research evidence.
- [ ] Public data has clear provenance and licensing.
- [ ] No secrets, private information or unlicensed data are added.
- [ ] Log entries accurately distinguish proposed, open, merged and deployed work.
